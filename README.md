# HSE App X — Web

Веб-клиент мобильного приложения HSE App X (`com.hse.app2`). Ходит напрямую в бэкенд приложения
(`api.hseapp.ru`), своего бэкенда нет.

```bash
npm install
npm run dev     # http://localhost:5173
npm run build   # тайпчек + прод-сборка в dist/
```

## Вход

У OAuth-клиента приложения (`app-x-android`) разрешён только redirect на схему `ru.hse.hseappx://`,
а браузер её открыть не может. Поэтому вход в два шага:

1. «Открыть страницу входа» → логин на официальном `saml.hse.ru`.
2. Скопировать адрес `ru.hse.hseappx://...?code=...`, на который браузер не смог перейти, и вставить
   его в форму. Если в адресной строке его нет: DevTools → Network → ответ с `Location: ru.hse.hseappx://…`.

Дальше access-токен обновляется сам по refresh-токену. Токены хранятся в `localStorage`.

## Без входа

Без токена бэкенд отвечает только на `/v3/dump/config`. Расписание, свободные аудитории, еда и поиск людей
требуют авторизации. Старый публичный API RUZ отключён. Гостю доступны главная и веб-навигатор
по корпусу (`navigation.hse.ru`, открывается в новой вкладке: встраивать его в iframe сайт запрещает).

## Архитектура — Feature-Sliced Design

```
src/
  app/       провайдеры, роутер (страницы грузятся лениво), глобальные стили и токены темы
  pages/     страницы: только компонуют слои ниже
  widgets/   крупные блоки: app-shell, auth-gate, week-picker, dashboard, user-profile
  features/  действия пользователя: auth, deadline-actions, people-search, free-rooms-filter, …
  entities/  бизнес-сущности: model (типы) + api (query-хуки) + ui (базовые карточки)
  shared/    http-клиент, auth/токены, конфиг API, UI-кит, утилиты
```

Правила: слой импортирует только из слоёв ниже. Слайсы одного слоя друг друга не импортируют.
Снаружи слайс доступен только через его `index.ts`.

Серверное состояние — TanStack Query. Ключи запросов объявлены в `entities/*/api/queries.ts`.

## Контракт API

Получен из APK 26.4.0 (декомпиляция jadx). Префиксы модулей — в `src/shared/config/api.ts`.
Типы ответов в `entities/*/model/types.ts` повторяют Gson-модели приложения (`@SerializedName`).
Все поля опциональные: бэкенд их не гарантирует.

Пока не реализовано (эндпоинты известны): бронирование помещений (`v2/events`), рейтинг-лидерборд
(`education/ratings`), заявки и сервисы (`tasks`), курсы LMS (`courses`), карьера и CV, справки,
оплаты общежития и обучения, СЭД, формы для иностранных студентов, группы дедлайнов.
